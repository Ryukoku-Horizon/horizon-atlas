View毎のファイル分割

前回(静的ルーティング)　｜　次回(ルーティングの練習問題)

a

今までのページで、複数ページを持つアプリの作り方を学びました。
しかし、このままページの数を増やしていくと、main.pyファイルがどんどん長くなり、どこに何が書かれているのか把握するのが難しくなってしまいます。

そこで、このページではPythonのimportという機能を使って、View毎にファイルを分け、コードを整理する方法を学びます。

目次

なぜファイルを分けるのか？

ファイルを分割することで、以下のようなメリットがあります。

・関心の分離
main.pyはページ遷移の管理（ルーティング）に専念し、各ページの見た目や機能はそれぞれのファイルで管理する、という役割分担ができます。

・可読性の向上
1つのファイルが短くなり、コードが読みやすくなります。

・保守性の向上
「情報ページのデザインだけ修正したい」といった場合に、info_view.pyだけを編集すればよくなり、他の部分を壊してしまう心配が減ります。

大規模なアプリを作る上では必須のテクニックです。

a

フォルダ構成の準備

まず、ファイルを分割して管理するためのフォルダを準備します。

flet createで作成したプロジェクトのsrcフォルダの中に、viewsという新しいフォルダを作成します。

1. srcフォルダ内にviewsフォルダを作成します。

2. 作成したviewsフォルダの中に、__init__.pyという空のファイルを作成します。これは、Pythonに「このviewsフォルダは一つの部品（パッケージ）ですよ」と教えるための重要なファイルです。

3. viewsフォルダの中に、カウンターページ用のcounter_view.pyと、情報ページ用のinfo_view.pyという2つのファイルを作成します。

作成後のフォルダ構成は以下のようになります。

保存する名前
  ├─ src
  │  ├─ assets
  │  │  ├─ icon.png
  │  │  └─ splash_android.png
  │  ├─ views                   <-- 作成
  │  │  ├─ __init__.py          <-- 作成 (空ファイル)
  │  │  ├─ counter_view.py      <-- 作成
  │  │  └─ info_view.py         <-- 作成
  │  └─ main.py
  ├─ .gitignore
  ├─ pyproject.toml
  └─ README.md

各Viewファイルの作成

次に、先ほど作成したファイルに、main.pyに書いていたViewのコードを移していきます。

重要なポイント

Viewを返す関数を作成し、その関数の引数としてpage: ft.Pageを受け取るようにします。こうすることで、分割したファイルの中からでもpage.push_route()のようなページ全体の操作が可能になります。

counter_view.py

カウンターページのViewを返す関数を定義します。カウンターの数字を管理する変数や、クリックされたときの関数もこのファイルにまとめます。

import文の書き方

毎度アプリを作るときに書くおまじないのimportについてです。

import は、別のファイルにある機能を読み込むための命令です。書き方は 2 種類あります。

① ファイルごと読み込む

python
1import flet

a

中身は flet.Text のように「ファイル名.使いたいもの」と書いて使います。

② 中の特定のものだけ読み込む

python
1from views.info_view import InfoView

a

views フォルダの info_view.py から InfoView だけを読み込みます。この場合は InfoView(page) とそのまま書けます。

as で別名を付けられる

どちらの書き方でも as で名前を変えられます。

python
1import flet as ft

a

毎回 flet.Text と書くのは長いので、ft.Text と書けるようにしている、というだけです。

a

main.py

最後に、main.pyを修正して、作成したView関数をimportして使うように変更します。

ここでは、前のページで学んだ「直接各ルートに遷移する場合」のコードをベースに修正します。

コード説明1

python
1import flet as ft
2
3from views.counter_view import CounterView # パスで場所を指定して特定の関数を読み込む
4from views.info_view import InfoView # 同様に関数を読み込む
5
6
7def main(page: ft.Page):
8    def route_change():
9        page.views.clear()
10
11        if page.route == "/info":
12            page.views.append(InfoView(page)) # ファイル内で作った関数を呼び出すことで表示
13        else:
14            page.views.append(CounterView(page)) # 同様に関数を呼び出す
15
16    page.on_route_change = route_change
17    route_change()
18
19
20if __name__ == "__main__":
21    ft.run(main)

if __name__ == "__main__": ってなに？

まず、__name__というのは、Pythonがファイルに対して勝手につける名札みたいなものです。

a

基本的にファイル名がそのまま__name__ になりますが、自分が最初に起動したファイル（今回だとmain.py ）はどんなファイル名でも__main__になります。


そのため if __name__ == "__main__": は、「このファイルが起動されたファイルなら、アプリを立ち上げる」という意味になります。
こう書いておくと、main.py が他のファイルから import されたときに勝手にアプリが起動してしまうのを防げます。Python ではほぼ必ず書く決まり文句なので、覚えておきましょう。

💡

単独で動かしてみよう

この仕組みを使うと、counter_view.py を単独で起動することもできます。ファイルの末尾に次を追加してみてください。

コード説明1

python
1if __name__ == "__main__":    
2		def main(page: ft.Page):        
3				page.views.clear()
4				page.views.append(CounterView(page))
5		ft.run(main)

a

同じファイルなのに、直接起動したときだけ ft.run が動いているのが確認できます。ページ単体の見た目を確認したいときにも便利です。

a

まとめ

main.pyから各ページの具体的な中身（ft.Textやft.ElevatedButtonなど）が無くなり、非常に簡潔になりました。

今のmain.pyの役割は、page.routeの値に応じて適切なView関数を呼び出す司令塔に徹しています。

👌

もちろん、スタック方式のルーティングも同様にファイル分割できます。
その場合もmain.pyのroute_change関数やview_pop関数の中で、ft.View(...)と書いている部分をCounterView(page)やInfoView(page)のような関数呼び出しに置き換えるだけです。
