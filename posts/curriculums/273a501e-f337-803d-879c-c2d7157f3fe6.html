ブランチを分ける

ブランチを分ける

ここではGitHubのブランチについて説明します

ブランチ

GitHubのブランチは、リポジトリ（プロジェクト全体）の中で「別の作業用の道」を作る仕組みです。

・mainブランチ

→ 公開する完成版の道。安定しているコードがここに置かれます。

・ブランチを作る

→ 「main から分かれる脇道」を作るイメージ。

その脇道では自由に工事（新機能追加や修正）をしても、本線（main）には影響しません。

・作業が終わったらマージする

→ 脇道での工事が終わったら、本線に道を合流させる（＝変更を取り込む）ことができます。

一文でまとめると

ブランチは「安全に別作業をするための分岐ルート」。本線に影響を与えずに試したり改良できて、必要なときに合流させられる仕組み。

ブランチの基本操作

ではまず、ブランチの基本操作の方法を説明します。

VSCodeでクローンしたリポジトリを開いてください。（リポジトリの作成・クローンはこちらで説明してます→🔰Git,GitHubのはじめ方 ）

ブランチの確認

ブランチは、git branchコマンドを実行すると確認できます

みなさんは実行すると* mainと出てくると思います

💡

実際の出力画像

git branchコマンドでは、「存在するブランチ」と「操作中のブランチ」を確認できます。

💡

存在するブランチが一覧で表示され、緑色で表示されたのが操作中のブランチです。

つまり、上記の出力の場合、存在するのはmainブランチのみで、操作中のブランチはmainブランチです。

ブランチの作成

ブランチを作成するにはgit checkout -b 新しいブランチ名というコマンドを実行します

実行例：

a

git checkout -b developは「developという名前のブランチ」を作成するコマンドです

このようにして新しいブランチを作成できます。

ちなみに、このコマンドでブランチを作成すると、自動で操作中のブランチが新しく作ったブランチに移動します。

この状態でgit branchコマンドを実行してみましょう

出力結果

a

出力からわかることは、developブランチとmainブランチが存在し、操作中のブランチはdevelopブランチということです。

操作中のブランチを切り替えるにはgit checkout 既存のブランチ名というコマンドを実行します。

git checkout mainと実行してみましょう。

このように現在操作中のブランチがmainブランチに切り替わりました

ブランチを分けて作業する

基本的にGitHubでは、mainブランチに完成版のコードをのせて、それ以外のブランチで作業を進めます。

なので、開発を進める時には基本的に、

・ブランチを分ける

・各ブランチで作業を進める

・問題なく機能を実装できたらmainブランチに統合（マージ）する

という流れになります

💡

mainブランチには常に実行可能な状態（完成版）のコードを載せておきましょう。

そうするとことによって、修復不可能なエラーが出ても、いつでも実行可能な状態に戻ることができます。

つまり逆にいうと、何か新しい機能を実装するなら、mainブランチ以外で作業すると良いということです。

実際にブランチを分けて内容を変更してみよう

まず、操作するブランチをdevelopブランチに切り替えます。

git checkout developコマンドを実行してください。

git branchコマンドで確認すると、操作中のブランチはdevelopブランチです

a

この状態で内容を変更します

ここでは試しに、develop.txtというファイルを作り、内容を書き込んでみます。

a

内容を書き込んだら、ファイル（develop.txt）を保存します。

それから、以下のコマンドを実行してください

・git add .

・git commit -m “developブランチを編集”

💡

pushはしないのか？

そう思った人もいると思いますが、ここではpushをしなくてもいいです。

ここでgit commitコマンドについて補足すると、このコマンドはそのリポジトリで変更を確定するコマンドです。もっと厳密に言えば、操作しているブランチ（developブランチ）での変更をローカル環境のリポジトリで確定するコマンドです。ローカル環境というのは、要は「あなたのPC内で」ということです。

つまり、git commitを実行し、git pushを実行しなければ、GitHubのネットワーク上にあるリポジトリには影響を及ぼしませんが、あなたのPC内のリポジトリで変更を確定するということです。

この状態で、git checkout mainコマンド（mainブランチに切り替えるコマンド）を実行してください。

すると、以下のようにdevelop.txtというファイル（developブランチで追加したファイル）が消えます。

a

developブランチで作業したとしても、mainブランチには影響を及ぼさないため、mainブランチは作業前と同じ状態なのです。

この状態でもう一度developブランチに戻ります（git checkout developコマンド）

すると、以下のように追加したファイルが戻ります

a

💡

このように、ブランチを分けると、分岐して安全に作業ができます

ブランチを統合（マージ）する

一度説明しましたが、基本的にGitHubでは、mainブランチに完成版のコードをのせて、それ以外のブランチで作業を進めます。

なので、他のブランチで作業が完了したら最終的にはmainブランチに統合する必要があります。

💡

ちなみに、統合することをマージ（merge）と言います

マージするには、取り込むブランチに切り替えてからgit merge 作業が完了したブランチコマンドを実行します。

ここでは、developブランチをmainブランチにマージしましょう。

まずmainブランチに切り替えます。（git checkout mainコマンド）

次に、git merge developを実行します（developブランチを統合するコマンド）

💡

実行結果：

a

すると、mainブランチにdevelopブランチで変更した内容が追加されます。

mainブランチに追加されている↓

a

このようにして、ブランチを分けて作業→ブランチを統合できます。

💡

ちなみに、ブランチをマージする時によくブランチ同士が競合状態になることがあります。その時は、競合エラーの原因と解決方法 で解説した解決方法でだいたい解決できます。

まとめ

ブランチとは、「安全に別作業をするための分岐ルート」。本線に影響を与えずに試したり改良できて、必要なときに合流させられる仕組み。

mainブランチには常に実行可能な状態（完成版）のコードを載せておきましょう。（修復不可能なエラーが出ても、いつでも実行可能な状態に戻ることができます。）
