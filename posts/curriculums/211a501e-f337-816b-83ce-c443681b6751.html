イメージとコンテナについて

Dockerを理解する上で重要となる要素が「イメージ」と「コンテナ」です。ここではその二つについて解説します。

コンテナについては前回ある程度解説したので、まずイメージについて説明します。

イメージとは

Dockerイメージは、コンテナを動かすための「設計図」や「テンプレート」のようなものです。

・アプリケーションを動かすのに必要なOS・ライブラリ・設定・アプリのコードなどをまとめたもの。

・イメージをもとにして、実際に動くコンテナが作られます。

つまり、イメージとは、コンテナの元となる設計図のようなものです。

また、イメージは配布することも可能で（DockerHubなど）、非常に高い再現性が持ちます。

イメージとコンテナの関係

すでに書きましたが、イメージをもとにコンテナが作られます。

イメージは設計図のようなもので、コンテナは設計図をもとに作られたインスタンスです。

ちなみに、同じイメージから複数のコンテナを作成することも可能です。そのため、一度作ったイメージは何度でも利用できます。

a

イメージの作成方法（dockerfile）

イメージを作成するには、dockerfileと言うコンテナの作成手順が書かれたファイルを用意する必要があります。

dockerfileには、例えば、どのベースOSを使うか、アプリのファイルをどう配置するか、何を実行するかなどを書きます。

例えば、以下のように書きます

docker

FROM python:3.11
WORKDIR /app
COPY . /app
RUN pip install -r requirements.txt
CMD ["python", "app.py"]

a
