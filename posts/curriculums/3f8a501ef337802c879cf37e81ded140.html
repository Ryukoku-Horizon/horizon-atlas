そもそもGit, GitHubとは

これらのツールは、一言で言うとプロジェクト(コード等)のバージョン管理、その共有を可能にするツールです。

Gitとは

Gitはそのうち、プロジェクトの「バージョン管理 」を請け負うシステムで、ローカル（自分のPC）で動作します。

GitHubとは

GitHubはそのうち、Gitの機能をインターネット上で、他の開発者と「プロジェクトを共有」・コラボレーションするためのプラットフォームです。

GitHubはGitをベースにしており、Gitのリポジトリ(Gitが管理している変更の内容)をインターネット上で共有することができます。

a

これだけは覚えておこう

Gitにはさまざまなターミナルのコマンドが存在しますが、特に重要なものが以下の四つです。

☝

「コマンドってなんだっけ？」と言う方は こちら→HorizonAtlasCLIの基礎

pull

他の人、もしくは別の所での変更を自分のコードにも適応するためのコマンドです。

使い方はリポジトリ内でgit pullです。

add

確定する変更を選ぶためのコマンドです。

今回は簡単のために全ての変更を選びます。その時の使い方ははリポジトリ内でgit add .です。

commit

変更をローカル(自分の環境下)で確定するためのコマンドです。

使い方はリポジトリ内でgit commit -m "メッセージ"です。

※メッセージの内容は任意ですが、絶対に何かしらは入力しなければいけません。

push

コミットで確定した変更をリモート(GitHub)へ送信・確定するためのコマンドです。

使い方はリポジトリ内でgit pushです。

a

よくあるエラー

not a git repository

これは簡潔に言うと、リポジトリをコピーしたフォルダでコマンドが実行されていないために「ここはgitのレポジトリじゃないよ！」と言われている状態です。

解決方法は簡単で、ターミナルのディレクトリをリポジトリまで移動してしまいましょう。

移動方法はcd レポジトリまでのパスです。

GitHubを使ってしりとりをしてみよう

始める前に

最初にリポジトリと言う「作業全体を送る場所・今までの変更が集約されている場所」をクローン(コピー)してローカルに持ってくる必要があります。

本来は自分で作ることもできますが、今回は用意した既存のリポジトリを使います。

ではクローンする前にいくつかすることがあります。

・GitHubを開いて、技術部長に自分のGitHubIDをDiscordのDMで送る

a

※写真中の画面右上、自分のアイコンを押して出てきているダイアログ中のアイコン横に書いてあるものがGitHubIDです(この写真の場合は「di-octer」がID)

・リポジトリの置きたい場所までターミナルで移動しておく

・GitHubのRyukoku-Horizon organisationにメンバーとして登録されるのを待つ

この三点が終わればクローンをしましょう。先ほどと同じ移動した後のターミナルで

bash
1git clone https://github.com/Ryukoku-Horizon/WordChain_on_README.git

a

を実行しましょう。

クローンが終われば、ターミナルでリポジトリの中に移動しましょう。

ここまで終われば準備完了です！

しりとりをしよう

今回はリポジトリにすでにあるREADME.mdファイルでしりとりをします。

ルール

基礎班運営に決めてもらった順番でしりとりをしましょう。

a

手順

1. 自分の番が来たらgit pullする

2. README.mdファイルで改行して次の単語を打つ

3. 単語が打ち終えたら、保存してから以下のコマンドを打ってGithubに適応する

bash
1git add .
2git commit -m "メッセージ"
3git push

a

4. 次の自分の番が来るまで待つ

※一人目の初手は「り」から始まる単語で手順2から始めましょう！

もし準備が不完全だとこんなエラーが出るかも
