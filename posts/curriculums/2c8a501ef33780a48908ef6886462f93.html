HTTPについて

HTTPとは通信のルールのようなもので、Webアプリは基本的にHTTPというルールで通信しています。このネットワーク通信でのルールをプロトコルと言います。HTTPはプロトコルの一種です。

なぜプロトコルが必要か

コンピュータ同士が勝手な形式でデータを送ったら——

・片方は JSON

・片方はバイナリ

といったことになりかねず、意思疎通ができないです。人間同士が共通の言語がないと話せないのと同じようなものです。

Webでのネット通信はHTTPによってデータの形式が決められています。

リクエスト

HTTPでは、クライアントがサーバーにリクエストするには

・URL（どこに送りたいのか）

・メソッド（何をしたいのか）

・ボディ（必要なデータ）

・ヘッダ（認証情報など）

を送ります

例（ログイン）：

POST /api/login
email=aaa@test.com
password=1234

a

POST（データの送信）がメソッドで、/api/loginがURL、email,passwordは送信するデータです。

💡

つまり、この場合/api/loginという場所に、email=aaa@test.com password=1234というデータの送信（POST）をしたいということです。

メソッドには、GET（データの取得）、POST（データの送信）、UPDATE（データの更新）、DELETE（データの削除）などがあります。

この形式によって、どこに求めるか、何をしたいか、何を送るか、がわかります。

レスポンス

レスポンスには：

・結果データ（HTML / JSON など）

・成功・失敗の情報（ステータスコード）

が含まれます。

例：

200 OK
{ "token": "xxxx" }

a

200 OKがステータスコードで、{ "token": "xxxx" }はJSON形式のデータです。

クライアントは、ステータスコードによって、リクエストが成功したかどうかを判別できます。200なら成功、400ならクライアント側の問題（リクエスト方法など）で失敗、500ならサーバー側の問題で失敗など。

結果のデータは基本的にHTMLやJSONです。HTMLであればブラウザがページを組み立て、画面に表示します。JSONであれば、基本的にJavaScriptがそのデータを元に何らかの処理をします。
