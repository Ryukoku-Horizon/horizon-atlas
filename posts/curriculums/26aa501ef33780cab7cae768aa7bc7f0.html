チーム開発での使い方

チーム開発でGit、GitHubを使う方法を説明します。

チーム開発でのGitHub使用の流れは以下のようになります

チーム開発でのGitHub使用の流れ

(1) GitHubでリポジトリを作成

(2) チームメンバーの一人がリポジトリを自分のPCにクローン

(3) (2)を行った人がPushする（初回Push）

(4) 他のチームメンバーがクローンする（全員がリポジトリをクローン）
ーーーーー↓開発開始↓ーーーーーーー

(5) それぞれローカル（自分のPC）で開発を進める

(6) コードができたら他の人と共有するために変更をPush

(7) (6)を行った以外の人がの変更をローカルに取り込む

(1)〜(3)は、前回と同様で、チーム開発の場合はそれに加えて(4)までがセットアップとなります。(5)〜(7)が開発中に行う操作です。

(1)〜(3)までは🔰Git,GitHubのはじめ方 で解説しているので割愛し、今回はチーム開発で必要な(4)〜(7)について説明します。

コードを共有する

ここからは実際に開発するときのコードの共有方法を説明します

共有は以下のような流れで行います

(1) それぞれローカル（自分のPC）で開発を進める

(2) コードができたら他の人と共有するために変更をPush

(3) (2)を行った以外の人が(2)の変更をローカルに取り込む

リポジトリの内容に変更を加える

まず、先ほどクローンしたフォルダ内で、何か変更を加えます。

変更したファイルを保存すると（ctrl + sまたはcommand + sで保存）、左のアイコンに数字が出ます。この数字は変更を加えたファイルの数です。（以下の画像ではREADME.mdのみに変更を加えたので1と表示される）

変更をPush

上記で行った変更を他の人と共有するためには、GitHubのリポジトリに、ローカル（自分のPC）で行った変更をPushしましょう。

pushをするには、ターミナルで以下のコマンドを順番に実行していきます。（前回の説明と同じ）

git add .

git commit -m “メッセージ”

git push

他の人の変更を取り込む

他の人が変更を加えてPushした場合、あなたはその変更を取り込む必要があります。

「変更を取り込むこと」をPull（プル）と呼びます。

a

Pullするには、git pullというコマンドをターミナルに入力し、実行（キーボードのEnterまたはreturnを押す）します

以下のように「Already up to date.」と表示された場合、現在のローカルの状態が最新の状態であることを示します。つまり、ローカル環境の状態とリポジトリの状態が同じであるということです。

まとめ

チーム開発を行うには、以下の流れで行います

「チームメンバー全員がリポジトリをクローンする」→「開発作業を進める」→「変更したらPushする」→「他の人がPullで変更を取り込む」

PushとPullは基本中の基本なので押さえておいてください（たぶんやってれば勝手に覚えます）
