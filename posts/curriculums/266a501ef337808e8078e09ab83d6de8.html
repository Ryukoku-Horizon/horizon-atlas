Git,GitHubのはじめ方

ここではGit、GitHubを始める上で必須となる操作方法を説明します。

Git,GitHubで開発をするとき、以下のセットアップをする必要があります

セットアップ

(1) GitHubでリポジトリを作成

(2) リポジトリを自分のPCにクローン

(3) 初回Pushする

今回はこの３つの操作を説明します

リポジトリを作成する

💡

リポジトリとは？

プロジェクトのフォルダみたいなもので、コードやドキュメント、設定ファイルなどをまとめて保存しておける場所です。GitHubでは、オンライン上でリポジトリにアクセスできるため、チーム開発をする際にコードやその他のファイルを共有することができます。

a

特徴をシンプルにいうと：

・📂 プロジェクトごとの保管庫：ソースコードやその他のファイルなどが入る。

・🌍 オンラインで共有可能：他の人と一緒に開発できる。

・⏪ 変更履歴が残る（Gitによるバージョン管理）。

・🔗 公開/非公開を選べる（オープンソースにしたり、自分だけのプライベートにしたりできる）。

つまり、GitHubのリポジトリ = プロジェクトのデータと履歴をまとめた保管庫 です。

👉 例えると、

・「パソコンのフォルダ」＋「過去の変更履歴」＋「クラウド共有」が合わさったもの、と考えると分かりやすいです。

リポジトリをクローンする

💡

リポジトリのクローンとは？

リポジトリのクローンとはGitHubにあるリポジトリをローカル（自分のパソコン）にコピーすることです。

a

ポイントを簡単に言うと：

・📥 ダウンロード＋Git管理付き：単なるダウンロードと違って、変更履歴も全部コピーされる。

・🖥️ ローカル作業が可能：コピーしたリポジトリの中で、ファイルを編集・追加できる。

・🔄 GitHubと同期できる：編集後にGitHubに「push」すれば、変更を共有できる。（pushについては後述）

👉 例えると：

・GitHubにある「プロジェクトの本」を、自分の机にまるごとコピーして持ってくる感じです。

・机の上で書き込み（編集）したら、またGitHubに送り返して（push）、みんなと共有できます。

pushをする（初回Push）

💡

pushとは？

GitHubでpushとは、自分のパソコン（ローカル）のリポジトリで行った変更を、GitHub上のリポジトリに送る操作のことです。

a

ポイントを簡単に言うと：

・✏️ ローカルでコードを編集して保存する。

・🚀 その変更をGitHubにアップロードするのが push。

・🌍 こうすることで、GitHub上でも変更が反映されて、他の人と共有できる（これでチーム開発が効率的に行える）。

pushをするには、ターミナルで以下のコマンドを順番に実行していきます。

git add .

git commit -m “メッセージ”

git push

実行動画

a

💡

git commit -m “メッセージ”について補足

”メッセージ”の部分は、実際の開発においてはそのpushがどのような変更を行なったかを説明する文章を入れます。チーム開発では誰がどのような変更を加えたのかがわかることが重要なので、できるだけ明確にどこをどのように編集したかを書いておきましょう。

例えば、アプリのトップページを編集した場合、git commit -m “トップページを編集”のように書きます。

GitHubのリポジトリのページにいき、以下のようにREADME.mdファイルが追加されていればpush完了です！

a

ここでは、リポジトリを作成してから最初のPushを「初回Push」と呼びます。初回Pushをするまでリポジトリは空です。

まとめ

ここではGitとGitHubを使い始める上で必要な操作を説明しました。

使い始めるには、上記のように、

・リポジトリを作成する

・リポジトリを自分のパソコンにクローンする

・リポジトリにデータをPushする

という操作が基本となります。
