競合エラーの原因と解決方法

競合エラーの原因と解決方法

ここではGit,GitHubでよく起こる競合状態と、その解決法であるマージの方法について説明します。

競合とは

まず振り返り：

・「Push」は、ローカルからリポジトリにデータの変更を送信する操作

・「Pull」はデータの変更を受け取る操作

競合とは

自分が他の人と同じファイルを変更したために、pushすることを拒否される状態が競合状態です。複数人が同じファイルを同時に変更すると、ファイルが破損してしまうため、gitがpushするのを拒否するようになっているのです。

図にするとこんな感じ

a

競合状態になると、以下のようなエラーが出ます

a

エラー文は「何らかの理由でリポジトリにpushできません」みたいな意味です。

解決法

競合した時に基本となる解決法は、「マージ」することです

💡

マージというのは、自分の変更と、他の人の変更を混ぜたものを作り、それをpushすることです。

競合状態になってみよう

そのまま説明してもわかりにくいと思うので、実際に今から競合状態にわざとしてみましょう。

まず、リポジトリを用意し、クローンしてください。（🔰Git,GitHubのはじめ方 で作ったものでいいです）

そしたら、リポジトリのページにアクセスしましょう

リポジトリのページ

a

README.mdというファイルがあるので、それを編集します。

鉛筆マークをクリックします

a

編集できる画面があらわれるので、何かテキトウに書き込んでください

a

書き込んだら、「commit changes…」というボタンを押してください

a

確認が出てくるので続けて「commit changes」をクリックします

a

これで内容を変更できました

次に、クローンしたフォルダをVSCodeで開きます

こちらのREADME.mdにも何かテキトウに書き込みます

a

ファイルを保存し、ターミナルでpushのコマンドを実行します

pushのコマンド

git add .

git commit -m “メッセージ”

git push

すると、競合状態となり、エラーが出ます

a

ここから本題で、エラーを解決していきましょう

まず、git pullを実行します（変更を受け取るコマンド）

次に、git mergeを実行します（マージするコマンド）

すると、VSCodeに以下のように表示されます

a

上がPushした自分の変更で、下がPullで受け取った変更です

a

マージの方法１

マージには色々方法がありますが、一つは単純に自分の変更に相手の変更を繋げる方法です

「Accept Both change」をクリックするとできます

a

以下のように自分の変更と受け取った変更が合体します

a

この状態になったらREADME.mdファイルを保存し、Pushするコマンドを実行すると競合状態が解決します

Pushするコマンド

git add .

git commit -m “メッセージ”

git push

この方法が一番無難だと思います。

マージの方法２

二つ目の方法はいったんpullで受け取った変更を全て受け入れてから、自分の変更をpushする方法です

「Accept Incoming change」をクリックすると、自分の変更は全て消えて受け取った変更のみ残ります。

a

これで競合は解決します。

💡

おすすめの方法は、変更を受け入れる前に、自分の変更をコピーして、どこかに保存してから、この方法で受け取った変更を受けれることです。そうすることで、自分の変更を後から追加するのが楽になります。

（コマンドで相手の変更を受け入れる場合はgit checkout --theirs .を実行）

他の解決方法

おすすめしませんが、自分の変更を強制pushすると競合は解決できます。

方法はpushコマンドに-fオプションをつけるだけです。

強制Pushするコマンド

git add .

git commit -m “メッセージ”

git push -f

これで、自分の変更で全て上書きできます。

これは相手の変更を無に帰すのでやるなら話し合ってやむを得ない場合にやりましょう（場合によっては喧嘩になるかも😅）

a
