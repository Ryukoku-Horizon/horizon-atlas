リモートとローカルについて

ここでは、リモートとローカルについて補足します。

リモート環境とローカル環境

基本的に、ネットワークを介してアクセスできる環境をリモート環境、オフラインでもアクセスできる自分のPCをローカル環境と言います。

gitは、ローカル環境でリポジトリの管理をするためのツールであり、githubはリモート環境でgitの機能を使用できて、コラボレーションできるプラットフォームです。

要は

・オフラインでもアクセスできる→ローカル環境

・オンラインじゃないとアクセスできない→リモート環境

リモートリポジトリとローカルリポジトリ

GitHubで作成したリポジトリはリモート環境にあるので、リモートリポジトリと言います。

GitHubのリポジトリをクローンすると、ローカル環境にリポジトリのコピーができます。このコピーされたリポジトリをローカルリポジトリと言います。

基本的には、「ローカルリポジトリで作業→pushしてリモートリポジトリで他の人に共有」というのがgithubを使った作業の流れです。

Pushするときのコマンドについて

Pushするときのコマンドは上記のリモートとローカルについての知識があると理解できます。

みなさんはPushするときに以下のように三つのコマンドを実行していると思います

git add .

git commit -m “メッセージ”

git push

それぞれ補足します。

git add

git add .というのは変更を確定するファイルを選ぶコマンドです

git add 変更を確定するファイル名という形で実行します。

例えば、git add test.pyを実行すればtest.pyを変更を確定するファイルとして選ぶことになります。

git add .のように、変更を確定するファイル名の部分に . をおくと、変更したすべてのファイルが選択されます。

💡

ちなみに、この変更を確定するファイルを選ぶことをステージすると言います

※ git addコマンドはあくまで変更を確定するファイルを選ぶコマンドであって、変更を確定するコマンドではないです。

git commit

・git commitコマンドは、変更を確定するコマンドです

先ほどのgit addコマンドで変更を確定するファイルとして選ばれた（ステージされた）ファイルの変更を確定し、変更履歴を残します。（だから、git commitコマンドを実行する前にはgit addコマンドを実行しておく必要がある）

ちなみに、ここで変更が確定して、変更履歴が残るのは、あくまでローカルリポジトリにおいてのみです。つまり、git commitコマンドは、ローカルリポジトリの内容の変更を確定し、リポジトリの内容を変更するコマンドなのです

git push

・git pushコマンドは、ローカルリポジトリでの変更をリモートリポジトリに送信するコマンドです。

つまり、git pushコマンドというのは、上記のgit commitコマンドで確定したローカルでの変更をリモートに送信するためのコマンドです。
