Push時のコマンドについて

前回(リモートとローカルについて)　｜　次回(ステージとコミットについて)

a

ここではPushするときのコマンドを前回の知識を踏まえて改めて説明します。

このページでGit・GitHubで使用する主なコマンドについて整理していきましょう。

前回のページをまだ読んでいない人は先に読んでおいてください。

目次

このカリキュラムではPushするときに以下の三つのコマンドを実行するようにと書きました。

git add .

git commit -m “メッセージ”

git push

今回は三つのコマンドについてそれぞれ補足します。

a

git add

git addコマンドは特定のファイルを「コミットするファイルを一時的に置いておく場所」に追加するコマンドです。コミットするファイルを一時的に置いておく場所を「ステージ」と言います。

コマンドの形式

bash
1git add <ステージに登録したいファイル名>

a

例えば、git add test.pyを実行すればtest.pyをステージに追加するファイルとして選ぶことになります。

git add .のように、変更を確定するファイル名の部分に . をおくと、変更したすべてのファイルがステージされます。

a

git commit

git commitコマンドは、変更を確定し、現在の変更をGitの履歴に残すコマンドです

コマンドの形式

bash
1git commit -m "コミットメッセージ"

a

先ほどのgit addコマンドでステージに追加されたファイルの変更を確定し、変更履歴を残します。（だから、git commitコマンドを実行する前にはgit addコマンドを実行しておく必要があります）

ちなみに、ここで変更が確定して、変更履歴が残るのは、あくまでローカルリポジトリにおいてのみです。つまり、git commitコマンドは、ローカルリポジトリの内容の変更を確定し、リポジトリの内容を変更するコマンドなのです。

a

git push

git pushコマンドは、ローカルリポジトリでのコミット内容をリモートリポジトリに送信するコマンドです。

つまり、git pushコマンドというのは、上記のgit commitコマンドで確定したローカルでの変更をリモートに送信するためのコマンドです。

下記の形式で実行します。

コマンドの形式

bash
1git push <リモート名> <ブランチ名>

a

<リモート名> <ブランチ名>は省略できますので、git pushだけで実行しても問題ありません。

よく使われるのはgit push origin mainです。

・origin … デフォルトのGitHubリポジトリへの接続名

・main … プッシュするブランチ名（他のブランチにpushしたい場合ここを変更する）

よく使うコマンド

・普通にPush

bash
1git push

a

すでにGitHubのリポジトリの接続先が設定されていれば、これだけでOK。

・初めてブランチを Pushするとき

bash
1git push -u origin my-branch

a

my-branchがリモートリポジトリに作成されます。（これを一度実行すれば次からはgit pushでOK）

・強制Push

bash
1git push -f

a

-fオプション（または—-force）をつけることで、強制的に自分の内容でリモートリポジトリを上書きできます。

a
