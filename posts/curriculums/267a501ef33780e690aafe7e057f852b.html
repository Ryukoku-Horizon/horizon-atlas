View毎のファイル分割

今までのページで、複数ページを持つアプリの作り方を学びました。
しかし、このままページの数を増やしていくと、main.pyファイルがどんどん長くなり、どこに何が書かれているのか把握するのが難しくなってしまいます。

そこで、このページではPythonのimportという機能を使って、View毎にファイルを分け、コードを整理する方法を学びます。

なぜファイルを分けるのか？

ファイルを分割することで、以下のようなメリットがあります。

・関心の分離
main.pyはページ遷移の管理（ルーティング）に専念し、各ページの見た目や機能はそれぞれのファイルで管理する、という役割分担ができます。

・可読性の向上
1つのファイルが短くなり、コードが読みやすくなります。

・保守性の向上
「情報ページのデザインだけ修正したい」といった場合に、info_view.pyだけを編集すればよくなり、他の部分を壊してしまう心配が減ります。

大規模なアプリを作る上では必須のテクニックです。

フォルダ構成の準備

まず、ファイルを分割して管理するためのフォルダを準備します。

flet createで作成したプロジェクトのsrcフォルダの中に、viewsという新しいフォルダを作成します。

1. srcフォルダ内にviewsフォルダを作成します。

2. 作成したviewsフォルダの中に、__init__.pyという空のファイルを作成します。これは、Pythonに「このviewsフォルダは一つの部品（パッケージ）ですよ」と教えるための重要なファイルです。

3. viewsフォルダの中に、カウンターページ用のcounter_view.pyと、情報ページ用のinfo_view.pyという2つのファイルを作成します。

作成後のフォルダ構成は以下のようになります。

保存する名前 ├─ src │ ├─ assets │ │ ├─ icon.png │ │ └─ splash_android.png │ ├─ views <-- 作成 │ │ ├─ __init__.py <-- 作成 (空ファイル) │ │ ├─ counter_view.py <-- 作成 │ │ └─ info_view.py <-- 作成 │ └─ main.py ├─ .gitignore ├─ pyproject.toml └─ README.md

各Viewファイルの作成

次に、先ほど作成したファイルに、main.pyに書いていたViewのコードを移していきます。

重要なポイント

Viewを返す関数を作成し、その関数の引数としてpage: ft.Pageを受け取るようにします。こうすることで、分割したファイルの中からでもpage.go()のようなページ全体の操作が可能になります。

counter_view.py

カウンターページのViewを返す関数を定義します。カウンターの数字を管理する変数や、クリックされたときの関数もこのファイルにまとめます。

python
1import flet as ft
2
3def CounterView(page: ft.Page):
4    counter = ft.Text("0", size=50, data=0)
5
6    def increment_click(e):
7        counter.data += 1
8        counter.value = str(counter.data)
9        page.update()
10
11    return ft.View(
12        route="/",
13        controls=[
14            ft.SafeArea(ft.Container(counter, alignment=ft.alignment.center), expand=True),
15            ft.ElevatedButton("情報ページへ", on_click=lambda _: page.go("/info"))
16        ],
17        floating_action_button=ft.FloatingActionButton(
18            icon=ft.Icons.ADD, on_click=increment_click
19        )
20    )

import文の書き方

毎度アプリを作るときに書くおまじないのimportについてですが、

まず使い方として、二種類存在します。

それはパスを使ってファイルを指定する「import パスによるファイル指定」（「import flet as ft」と同じ）のような方法と、

「from パスによるファイル指定 import そのファイル内の特定の関数など」という方法です。

また、どちらもasを使ってこのファイル内での名前を付けなおして扱いやすくできます。

これによって、前者ではasを使った場合ファイル中の関数などをすべて使え、具体的には「付けなおした名前.使いたい関数など」、

後者では「そのファイル内の特定の関数など 」をそれに準じた方法で使うことによってimportしたファイルでも使うことができます。

main.py

最後に、main.pyを修正して、作成したView関数をimportして使うように変更します。

ここでは、前のページで学んだ「直接各ルートに遷移する場合」のコードをベースに修正します。

python
1import flet as ft
2from views.counter_view import CounterView  # パスで場所を指定して特定の関数を読み込む
3from views.info_view import InfoView  # 同様に特定の関数を読み込む
4
5def main(page: ft.Page):
6    def route_change(route):
7        page.views.clear()
8
9        if page.route == "/info":
10            page.views.append(InfoView(page))  # ファイル内で作った関数を呼び出すことで表示
11        else:
12            page.views.append(CounterView(page))  # 同様に関数を呼び出す
13
14        page.update()
15
16    page.on_route_change = route_change
17    page.go(page.route)
18
19ft.app(main)
20

a

main.pyから各ページの具体的な中身（ft.Textやft.ElevatedButtonなど）が無くなり、非常に簡潔になりました。

今のmain.pyの役割は、page.routeの値に応じて適切なView関数を呼び出す司令塔に徹しています。

👌

もちろん、スタック方式のルーティングも同様にファイル分割できます。
その場合もmain.pyのroute_change関数やview_pop関数の中で、ft.View(...)と書いている部分をCounterView(page)やInfoView(page)のような関数呼び出しに置き換えるだけです。
